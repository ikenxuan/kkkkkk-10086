# 缓存复用与清理

## 调查结论

2.41.0 已有独立 `mkdtemp` 工作目录和截图 `finally cleanup`，正常路径不缺清理调用。历史构建 `adbcd677`（2.41.0）和 `7b0ea608`（2.39.1）都能验证这一点。

真正的缺陷是删除前先设置 `cleaned=true`，失败后不能重试；SSR catch 和截图 finally 直接等待清理，又会用清理异常覆盖业务异常。进程异常退出绕过 finally 后，也没有启动或周期兜底。更早的渲染产物还使用过 `kkkkkk-10086-render-*`，旧 art-template 路径则把编译输出交给宿主管理。

生产曾有 50,970 个、约 29.5 GiB 的旧 HTML，且均超过七天；这些已经人工清除。`temp/html/kkkkkk-10086/*.html` 与旧宿主编译输出相符，而当前 standalone 生成 `kkkkkk-10086-ktr-*`。仅凭现存源码和文件年龄，不能证明所有历史文件都来自同一个版本、异常退出或删除失败；需要旧宿主代码和当时日志才能逐一归因。本次没有访问或清理生产环境。

## 哪些内容会复用

| 类型 | 复用方式 | 本次策略 |
| --- | --- | --- |
| standalone HTML | 每次新目录、每次截图 UUID，不复用 HTML | 截图及内存分片的真实 Promise 结束后清理；清理失败不影响原结果，可重试 |
| 抖音弹幕条 HTML/PNG | 单次烧录内用局部 Map 合并相同样式与文本，PNG 被 FFmpeg 多次引用 | 生产调用放入当前媒体目录，保留到 FFmpeg 结束再清理；不提前按单次截图结束删除可复用 PNG |
| 模板模块、构建产物 | 模块加载 Promise 与共享静态资源复用 | 不参与运行缓存清扫，不删除 `lib`、模板或资源目录 |
| API 查询缓存 | 既有内存缓存按 API 策略复用 | 保留原有策略，不改 API TTL |
| 媒体工作文件 | 下载断点续传、转码、多群/多订阅者发送、合并转发与预览读取会复用 | 独立工作目录，最后一个真实消费者结束后保留 10 分钟，访问预览可续期 |
| 已存在的同名下载文件 | 既有下载逻辑是截短后 Range 续传，不是完整文件直接命中 | 不新增跨请求完整文件缓存；每个解析工作区隔离，同一操作的重试仍可续传 |
| `removeCache:false` 的标题文件 | 用户要求保留的视频、图片、BGM 等存档 | 继续使用原存档路径，不迁移，不纳入自动或手动兜底清扫 |
| 调试 HTML/数据快照 | 人工排错需要短期复现 | 仅 `KKK_TEMPLATE_CAPTURE=1` 显式开启保留；24 小时有效期及独立容量限制 |

媒体 scope 附着于实际任务，不附着于超时 guard 的返回值。外层等待超时而下载、转码或发送仍在继续时，租约仍有效。嵌套任务共用工作区并分别持有消费者引用，迟到回调在旧 scope 结束后必须建立新工作区。

直播预览录制源文件由所有订阅者消费完成后释放，压缩器不再擅自删除共享输入。预览 HTTP 的全量读取和 Range 读取持有磁盘租约，流关闭或客户端断开后才释放。对旧路径的兼容删除计划按最后上传消费者延期，并核对文件身份，避免旧定时器删除同名新文件。

## 默认策略与配置

配置位于 `app.yaml` 的 `cache` 节，锅巴基础配置面板同步提供设置；修改后重启生效。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `orphanHours` | 24 小时 | 无活跃租约的异常退出工作目录有效期 |
| `legacyHours` | 168 小时 | 旧插件 HTML 有效期 |
| `mediaMinutes` | 10 分钟 | 最后媒体消费者结束后的复用窗口 |
| `maxFiles` / `maxSizeMB` | 1000 / 256 MiB | 一般受管缓存的数量与空间回收阈值 |
| `sweepMinutes` | 30 分钟 | 常规兜底间隔 |
| `debugHours` | 24 小时 | 显式保留的调试工作目录有效期 |
| `debugMaxFiles` / `debugMaxSizeMB` | 50 / 64 MiB | 调试文件的独立回收阈值 |

启动后延迟一秒开始异步清扫，不阻塞数据库或应用加载。有积压时每秒分轮继续，完成后回到常规间隔。清理失败时退回常规间隔，避免每秒重复失败日志。没有外部 cron；旧的每日/手工清理入口也复用同一个安全清扫器，不再无条件清空媒体目录。

每轮最多扫描 500 项、执行 100 次文件/目录删除操作，通常最多释放 64 MiB。单个文件大于该字节预算时，允许作为该轮首个文件执行一次 unlink，避免大视频永远无法回收。遍历使用增量目录游标，候选窗口最多 2048 项，不一次性加载五万条文件名再并发删除。

数量和空间限制是渐进回收阈值，不是允许删除活跃文件的硬配额。活跃进程租约、外机或不明租约、路径安全检查始终优先；容量驱逐还要求至少闲置一小时。媒体到期则按其复用 TTL 回收。存活但挂起的进程可能继续占用工作区，不能为了追求配额强删。

## 所有权与安全边界

只处理以下位置及明确命名的产物：

- 宿主 `temp/html/kkkkkk-10086` 内的旧 HTML（包含路由子目录）；非 HTML 文件保留。
- `temp/html/kkkkkk-10086-ktr-*`、旧 `kkkkkk-10086-render-*`、`kkkkkk-10086-debug-*`。
- 新媒体工作区 `temp/kkkkkk-10086/.cache/media-*`，及回收过程中生成的专用隔离名称。

新工作区具有有界 JSON 所有权元数据和独立消费者租约，记录主机、PID 与随机标识。清扫者不只依靠单进程 Set：本机活 PID、外机租约或无法确认的记录均保守跳过；死进程遗留按有效期处理。回收声明与新读者租约有互斥检查，领取后再核对期限，防止预览续期与清扫竞争。

所有祖先路径与子项均检查链接，拒绝符号链接和 Windows Junction，不跟随链接目标。只删除受管工作区或明确的旧 HTML，不读取其业务内容来判断归属。不扫描其他插件、配置、数据库、模板树、系统临时目录或传统用户存档。旧 `kkkdownload` 内没有归属标记的文件不按名字或年龄猜测删除。

租约释放、目录删除和中断恢复都允许重试。增量回收保留控制信息到有效载荷处理完毕，避免进程在半途中退出后丢失归属依据。清理日志只记录数量、字节和错误码摘要，不输出文件名、消息内容、模板 props 或凭据。

## 调试兼容性

`KKK_TEMPLATE_CAPTURE=1` 仍是显式保留开关，但快照不再永久写进 `ktr/template`。HTML 与 `capture/<route>/data/captured.json` 一起保存在有期限的 `temp/html/kkkkkk-10086-debug-*` 中，需要回放时可自行导入本地开发面板。未开启时不保留工作目录；即使 `NODE_ENV=development`，SDK 自动捕获也被限制在本次临时目录。

手工存放在模板树的历史快照不会被扫描或删除。请勿将带真实群聊内容的快照、生产缓存或调查日志提交到 Git。
